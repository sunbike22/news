# 動きのチェック(手で動かすテスト)

ブラウザを自動で動かして、「押してもエラーが出ないか」「ちゃんと反応するか」を見る。
サイトを大きく変えたあとに動かす。

## 使い方

```
cd /home/claude/news
python3 -m http.server 8766 &            # サイトをローカルで出す
S=<しらべもの用フォルダ> NODE_PATH=/tmp/node_modules node tools/test/crawl.js
S=<しらべもの用フォルダ> NODE_PATH=/tmp/node_modules node tools/test/flows.js
```

`S` には、外のライブラリの控え(`libs/`・`chart.umd.js`)と `alert_real.json` を置いておく。
ネットにつながらないので、jsDelivr と alert.json は差しかえている。

- `crawl.js` — 全タブの押せるものを1つずつ押して、エラーが出たものを出す。
  「🔊」のボタンは音を出すだけなので、画面が変わらなくても正常。
- `contrast.js` — 9色 × 明るい/暗い × 5タブで、文字と背景のコントラスト比を測る。`種類: 0` が合格。
- `zoom.js` — 地図と捜査ボードを2本指でひろげて、大きくなるか・今までの操作が残っているかを見る。
- `flows.js` — 打ちこみ・切りかえ・保存など、押すだけでは出ない動きを1つずつ確かめる。
  最後に `NG の数: 0` が出れば合格。

- `health.js` — 定期の不具合チェック(週2回の定期タスク「アプリの不具合チェック」もこれを動かす)。はじめての人・ふつう・かんたん・暗い画面・パソコン幅で全タブと主な画面を開き、エラー・横はみ出し・開きっぱなし、ペットの絵(6種類×段階×気分×服)、名人→新しいたまご、データの形を見る。`NG: 0` が合格。
- `setup.sh <フォルダ>` — Playwright と外のライブラリの控えを npm からそろえる(新しい環境で最初に1回)。
- アプリは localhost で開いたときだけ `window.NW_TEST`(petSVG・WEAR・ME など)を出す。テストはこれを使う(本番では出ない)。

## 気をつけること
- シートを閉じるときに `innerHTML` を空にしてはいけない。
  アプリが見ている要素が消えて、本物ではないエラー(`... of null`)がたくさん出る。
- 読み上げ(speechSynthesis)とクリップボードは、画面なしのブラウザでは動かない。
  `prompt` が出るのは、クリップボードが使えないときの逃げ道なので正常。
